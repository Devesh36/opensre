## Overview

A **remote runtime** is an OpenSRE deployment on Railway, EC2, Docker, or another host. Investigations use the same RCA pipeline as local runs: you pass an alert payload (file, JSON, or interactive paste) to `opensre investigate`, optionally against the deployed instance's integrations and alert listener.

The current CLI does **not** expose `opensre remote` or `opensre investigate --service <name>`. Gather logs, metrics, or alert JSON from your host or observability tools, then investigate with `-i` / `--input-json` / `--interactive`.

## Prerequisites

1. **Deploy OpenSRE** — see [Deployment](/deployment) for Docker, gateway mode, and environment variables (`LLM_PROVIDER`, provider API keys, optional `DATABASE_URI` / `REDIS_URI`).
2. **Configure integrations** on the deployed instance (same env vars and `opensre integrations setup` flow as local).
3. **Optional alert listener** — set `OPENSRE_ALERT_LISTENER_TOKEN` so remote callers can POST alerts to the runtime (documented on the deployment page).

## Run an investigation

From your laptop or from the deployed host:

```bash
opensre investigate -i path/to/alert.json
opensre investigate -i alert.json --output ./rca.json
opensre investigate --interactive
```

Wire alerts from your monitoring stack into a JSON file or POST body, then use one of the paths above. Output matches a local run: `problem.md`, hypothesis files, and `report.md` (or JSON with `--output`).

## Gateway and messaging on a deployed host

For Telegram two-way chat and background scheduling on a deployment, use gateway mode:

```bash
opensre gateway start
opensre gateway status
```

See [Deployment](/deployment) and [Messaging](/messaging) for gateway env vars and channel setup.

## Interactive shell

In the REPL (`opensre`), describe the incident in plain language or use `/investigate` with a template. Slash command `/remote` is registered for CLI parity but forwards to `opensre remote`, which is **not** on the current top-level CLI — prefer `opensre investigate` and [Deployment](/deployment) for remote workflows.

## Local agent fleet (separate from hosted runtime)

To discover other AI coding agents on **this machine**, use fleet scan (not a hosted OpenSRE service):

```bash
opensre fleet scan
opensre fleet scan --register
```

See [Local Agent Fleet](/fleet).

## Slack or chat context in an alert

Include Slack thread text, pager links, or runbook URLs inside the alert JSON you pass to `investigate -i` (or build the payload interactively). There is no `--slack-thread` flag on the current `investigate` command.
